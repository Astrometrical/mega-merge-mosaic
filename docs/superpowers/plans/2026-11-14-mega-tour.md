# `mega-tour` Recorder and the NGC 7000 Tour Implementation Plan (narration project, plan 3 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Record scripted, narration-paced walkthroughs of any egui app, headless, into a silent video, a timeline and captions that `narrate mux` turns into a narrated video. The spike's NGC 7000 tour is the first one.

**Architecture:** a new Rust library crate, `crates/mega-tour`. It depends on egui, egui_kittest (wgpu), image, serde and serde_json, and `mega-ui` (overlay styling from theme tokens). It never depends on `mmm-*`. It has three parts:
- **A pure timing core:** the manifest model, the caption and speech schedule, and the VTT and timeline writers. It is unit-tested without a GPU.
- **A GPU recorder:** the spike's `Rec`, `Overlay`, `NoTestCursor` and ffmpeg pipe, made generic over the app's state.
- **The app's tour:** `mmm-app` holds it as an `#[ignore]`d test, using the tour narration script from plan 1, plus a runner script that chains narrate build, then record, then mux.

**Tech Stack:**
- **Rust:** 2024 edition; egui and egui_kittest 0.36 (wgpu); image 0.25; serde and serde_json; `mega-ui`.
- **External tools:** ffmpeg, and the `narrate` CLI from plans 1 and 2.

## Global Constraints

- **CLAUDE.md conventions apply:**
  - UI values come from `mega_ui::theme` tokens, never literals (exception: the cursor's arrow geometry and its black/white/shadow colours, as in the spike).
  - Every public item has a doc comment.
  - `cargo fmt`, `cargo clippy --all-targets -- -D warnings` (also with `cargo +1.100.0`, since CI uses the latest stable) and `cargo doc` are warning-free.
  - Tests synthesise their inputs; there is no `test_data/`.
  - GPU tests are `#[ignore]`d, with the reason in the attribute.
- **`mega-tour` never depends on `mmm-core` or `mmm-app`.** `mega-ui` is allowed; the two lift out together.
- **Timing** is in output frames, as in the spike:
  - **Defaults:** `FPS = 30`; `LEAD` and `BREATH` come from the manifest (0.15 s and 0.4 s), and the config may override them.
  - **Time-lapse waits:** they capture 1 frame per `speed` steps, so narration stays in sync with the output video.
  - **Wall clock:** every `wait` step is paced to a real frame time, because the app's jobs run on wall-clock threads.
- **Manifest parsing** (`narration.json`, spec §8.4) is strict:
  - `"version": 1` only.
  - Fields the recorder needs are typed: `lines[].id`, `text`, `kind`, `clip` (string or null), `duration`, `status`, `captions[{text, start, end}]`, and the top-level `draft`, `lead` and `breath`. Unknown fields are ignored, so `narrate` can add fields.
  - `check.pace` may be null and `check` may be null; nothing here reads them.
  - **Vocabulary** (spec §8.4, as built in plan 2):
    - `status` is one of `approved`, `new`, `flagged` or `draft`; reject anything else.
    - `flags` (not read here) can include `words`, `pace` or `pinned-audio-missing`.
    - `check.sha256` exists, but the recorder doesn't need it.
    - The recorder records unapproved lines without complaint. `narrate mux` is the gate.
- **Outputs**, in the recorder's output directory:
  - **`silent.mp4`:** H.264, `yuv420p`, `+faststart`, CRF 18, preset medium, as in the spike.
  - **`timeline.json`:** spec §8.5: `{"version": 1, "video": "silent.mp4", "narration": <path to the manifest, relative to the output dir when possible, else absolute>, "fps": 30, "cues": [{"id", "start"}]}`.
  - **`captions.vtt`:** WebVTT, one cue per displayed caption entry.
  - **Stills,** on request.
- **The stage:** logical 1280 × 720 at 1.5 pixels per point, which renders at 1920 × 1080.
- **Commits:** conventional style (`feat(tour): …`), ending with the committing model's Co-Authored-By line.

## Review Focus

1. **A `say` for an id not in the manifest:** panics with the id, and the list of known ids, before any frame is written. Covered by Task 2's `unknown_line_id_is_named`.
2. **A draft manifest** (`clip: null`, estimated durations): pacing still works and the timeline is still written, while `narrate mux` refuses it later. Covered by Task 2's `draft_lines_pace_by_estimated_duration`.
3. **A passage's sentence captions:** they switch at their scheduled frames during a time-lapse `wait`, never by wall clock. Covered by Task 2's `captions_switch_in_output_frames`.
4. **Two `say` calls with no actions between:** the second waits for the first clip plus the breath, so clips never overlap in the timeline. Covered by Task 2's `say_waits_for_previous_speech`.
5. **A VTT file with a caption still open at `finish`:** it is closed at the final frame, with no zero-length or negative cues. Covered by Task 2's `vtt_closes_open_caption_at_finish`.

### Task 2: The schedule, VTT and timeline (pure timing)

**Files:**
- Create: `crates/mega-tour/src/schedule.rs`, `crates/mega-tour/src/outputs.rs`

**Interfaces:**
- Consumes: `Narration` and `Line` (Task 1).
- Produces (`schedule.rs`):
  - `frames(secs: f64, fps: u32) -> u64`, which rounds.
  - `Schedule::new(narration: Narration, fps: u32, lead: f64, breath: f64) -> Schedule`.
  - **`say(&mut self, id: &str, now: u64) -> u64`:** returns the frame the clip starts on. It panics with the id and the list of known ids when the id is unknown. Callers have already advanced `now` to `speech_until()`. It ends any open caption at `now`, and schedules the line's captions:
    - the first caption shows from `now`;
    - caption k > 0 shows from `clip_start + frames(c.start)`;
    - each shows until the next one starts;
    - the last stays until the next `say` or `clear`.

    It sets `speech_until = clip_start + frames(duration + breath)`, and records the cue `(id, clip_start)`. A line may be said more than once, and each `say` adds its own cue: since plan 2, `narrate mux` accepts duplicate cue ids (spec §8.5).
  - `speech_until(&self) -> u64`.
  - **`caption_at(&self, frame: u64) -> Option<(&str, u64)>`:** the caption text and the frame it appeared on, for the fade-in.
  - **`clear(&mut self, now: u64)`:** ends the open caption at `now`, so no caption shows until the next `say`.
  - **`finish(&mut self, last: u64)`:** closes any open caption at `last`.
  - `cues(&self) -> &[(String, u64)]`.
  - `captions(&self) -> Vec<(u64, u64, String)>`: closed caption spans in frames, in order, dropping any span of zero length.
- Produces (`outputs.rs`):
  - `write_vtt(path, spans: &[(u64, u64, String)], fps) -> io::Result<()>`, with timestamps as `HH:MM:SS.mmm`, as in the spike.
  - `write_timeline(path, video: &str, narration: &Path, out_dir: &Path, fps, cues: &[(String, u64)]) -> io::Result<()>`. The narration path is relative to `out_dir` when it is inside it, else absolute, always with forward slashes. Starts are `frame / fps` seconds, rounded to milliseconds.
